Knife TCP pivot calibration

A local, plan-only workflow for calibrating the knife tip directly from live MoveIt/TF poses. It computes the fixed igus_tool0 → xeg32_tool_tip translation from a common-point pivot; it does not send robot commands.

Recommendation

Use the existing MoveIt Servo + TF stack and this local pivot solver; do not add an external calibration package. The upstream moveit_calibration repository is a camera/robot hand-eye tool, documented as developed and tested on ROS Melodic/Noetic—not a TCP-pivot UI or a Humble TCP solution. industrial_calibration likewise targets camera/robot-system calibration. MoveIt Setup Assistant defines groups/end effectors, but does not measure a mounted tool TCP.

This workspace already exposes the required integration point: link6 → igus_tool0 → xeg32_tool_tip. MoveIt Servo already uses xeg32_tool_tip as its end-effector frame. The only persistent model change after acceptance is the translation in igus_tool0_to_xeg32_tool_tip.

Safety gate — complete before moving

The calculator remains available for recorded data. The “ready” button only confirms the checklist inside this page; it cannot enable or command the robot.

Why a pivot calibration works

At each sample, hold the same physical knife tip on one fixed pivot while changing robot orientation. If pᵢ, Rᵢ are the live base_link → igus_tool0 translation and rotation, this tool solves pᵢ + Rᵢr = c for the TCP translation r in igus_tool0 and the stationary pivot c in base_link. A low residual means one rigid offset explains all samples.

What it calibrates

Knife-tip position relative to igus_tool0.

What it does not calibrate

Blade roll/pitch/yaw, collision geometry, or a flexible zip-tie mount.

Required data

At least 5 poses; 8–12 well-spread orientations is preferred.

2
Run the record-only TCP GUI alongside your existing teleop.
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch rebel_tcp_gui tcp_gui.launch.py

The GUI is record-only: it publishes nothing and commands no motion. Move the arm with your existing teleop, hold the tip stationary on the pivot, then press Capture. Capture stays disabled until all four safety boxes are checked. The GUI stores live base_link → igus_tool0 TF rows, solves the same pivot least-squares in-app, and only displays the igus_tool0_to_xeg32_tool_tip snippet for hand application — it never edits the Xacro itself.

Keyboard alternative: ros2 run igus_rebel_moveit_config rebel_servo_teleop_keyboard. Select the xeg32_tool_tip command frame with e before orientation jogs (w returns to the base_link planning frame). On Jazzy, also select Twist input with t; Humble Servo accepts twist and joint commands at any time. On Humble the keyboard node calls /servo_node/start_servo itself when it starts; Servo needs run_teleop:=true in the MoveIt launch. The end-effector frame is xeg32_tool_tip; do not use the old, uncalibrated green marker as proof that the physical tip is correct.

Safe orientation control scheme. Orientation keys publish direct Cartesian angular Twist commands: i/k ±roll about X, n/m ±pitch about Y, u/o ±yaw about Z. j selects joint jog on Jazzy (no effect on Humble) and is not an orientation key. - and = decrease and increase the Cartesian linear and angular speeds together (default 5 mm per key press and 0.15 rad/s; reduce the step with the /servo_keyboard_input/set_cartesian_increment service, range up to 0.03 m). Start at the slowest speed and raise it only as far as gentle pivot contact requires.

No random, autonomous, or predefined physical motion is used. Random or scripted rotation cannot guarantee the knife tip stays on the fixed pivot, so it risks slipping, bending the tool, and producing non-reproducible samples. Deterministic operator-selected orientations — the operator jogs to each orientation, returns the physical knife tip to the fixed pivot, verifies light stationary contact, then records the pose — are safer and reproducible.

Recommended operator-reached sample orientations (manual targets, not automated motions). From a comfortable home pose with the tip on the pivot, the operator manually reaches roughly: (1) nominal tool-down; (2) rolled ~+20°; (3) rolled ~−20°; (4) pitched ~+20°; (5) pitched ~−20°; (6) yawed ~+30°; (7) yawed ~−30°; (8) a combined roll+pitch tilt of ~15° each. Return the physical tip to the exact pivot point after every move and record only when contact is light and stationary. Add further spread (up to 8–12 samples) only with the same manual return-to-pivot check each time.

3
Read the parent-frame pose while the physical knife tip is stationary on the pivot.
ros2 run tf2_ros tf2_echo base_link igus_tool0

Record one stable transform after every substantial orientation change. Keep contact gentle; do not slide or bend the tool. Avoid samples that differ only by translation or only by a few degrees.

Local TCP calculator

Accept, apply, and validate

1
Reject weak fits.

Inspect every sample and redo any contact that slipped. As an operator acceptance rule, aim for RMS residual ≤ 1 mm and maximum residual ≤ 2 mm for a rigid knife mount. A larger result is evidence of inconsistent pivot contact, insufficient orientation spread, TF/joint-state error, or tool flex—not a number to average away.

2
Apply only the reported translation.

Update the <origin xyz="…" rpy="0 0 0"/> in the fixed joint igus_tool0_to_xeg32_tool_tip in src/igus_rebel_description/urdf/igus_rebel_xeg32_wrapper.urdf.xacro. Preserve the parent and child links. Do not change joint origins elsewhere to compensate.

3
Rebuild and restart, then verify without cutting.
colcon build --packages-select igus_rebel_description igus_rebel_moveit_config --symlink-install
source install/setup.bash
# Restart robot-state publisher and MoveIt after changing the model.
ros2 run tf2_ros tf2_echo igus_tool0 xeg32_tool_tip

Use slow Servo jogging to place the physical tip on the pivot from several fresh orientations. The green marker must coincide with the physical tip before any planning near a fixture.

4
Calibrate blade orientation separately.

Pivot calibration provides position only. Set the fixed-joint RPY only after a separate, physical orientation reference establishes the blade normal and cutting direction. Then add conservative attached-tool collision geometry before relying on collision checking.
