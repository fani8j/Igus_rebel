igus ReBeL · ROS 2 Humble · operator guide

Staged cut debug
with Servo teleop

Plan the start point of one left, middle, or right cut; inspect it; explicitly dispatch it; correct the TCP with MoveIt Servo; save the observed full pose; then teleoperate to the endpoint and save it. Only the start is ever planned and executed by the executor.

Physical motionRead before running

Commands here can move the robot

The HTML is a static tutorial: buttons only copy text. A pasted execute_planned_h_cut call can move hardware when both executor gates are enabled. Servo teleop bypasses those executor gates; control Servo with its pause and unpause services.

Use mock hardware for the complete first run. For a physical run, clear the workspace, verify the selected plan in RViz, use low speed, keep an emergency stop reachable, and keep only one active robot controller/client.

Session invariant

plan point→ execute→ teleop→ save

Then teleop to the endpoint and save again. Stages: start_planned → start_executed → start_saved; the endpoint save writes the complete record and ends the session. No save plans, retains, or executes anything; there is no lift stage.

Prerequisites

Build, source, perception, and collision geometry.

No motion
  • Build the workspace with ROS 2 Humble.
  • Provide a recent external snapshot JSON from a previously captured perception workflow (no live camera required). This repository consumes that file but does not contain the capture publisher.
  • Ensure the carton collision geometry is valid before planning. The camera is fixed outside the robot: no camera or holder is modeled on the gripper, but the external camera TF and required camera_pole collision object must be available. The green xeg32_tool_tip marker remains the kinematic TCP with no collision geometry of its own.
  • For physical use, position the controller in the intended operating mode and stop every competing CRI/controller client.

cd /home/farhan/igus_rebel_ros2

colcon build --symlink-install --packages-select igus_rebel_moveit_config

Snapshot freshness: start_cut_debug_session refuses a snapshot older than external_snapshot_max_age_s (240 s in the supplied box_h_cut_executor.yaml; read-only, allowed range (0, 600] s). Once the session has started, its snapshot is frozen and the later teleop/save steps are not age-checked.

debug_allow_stale_snapshot is a plan-only override for inspecting an old snapshot in RViz. A session or plan loaded with it (or anything while it is true) is refused by execute_planned_h_cut before every other gate, so it cannot be used for a session you intend to execute. For a real session, produce a fresh snapshot and start within the age limit.

Plan, inspect, and execute the start point

The session begins with one retained point-to-point plan.

Plan firstExplicit dispatch
Select cut and plan configured start
ros2 param set /box_h_cut_executor cut_debug_cut __CUT__
ros2 service call \
  /box_h_cut_executor/start_cut_debug_session \
  std_srvs/srv/Trigger {}
Inspect before continuing. In RViz, verify the selected cut, start target, approach direction, carton collision geometry, and trajectory. If a correction record is active, it seeds this target; the newly saved record still references uncorrected geometry and replaces it as a standalone correction. This call never dispatches motion.
Authorize exactly this planned dispatch
ros2 service call /servo_node/pause_servo std_srvs/srv/Trigger {}
ros2 param set /box_h_cut_executor execution_enabled true
ros2 param set /box_h_cut_executor debug_motion_execution_enabled true
ros2 service call \
  /box_h_cut_executor/execute_planned_h_cut \
  std_srvs/srv/Trigger {}
ros2 param set /box_h_cut_executor debug_motion_execution_enabled false

The execute service returns when the dispatch is accepted, not when motion completes. Confirm the executor logs H-cut trajectory execution completed and the robot has stopped at the intended point before unpausing Servo. If execution fails, the stage is not marked executed and the session must be cleared and restarted.

Teleop-correct and save the start

Capture full observed TCP pose from fresh joint-state FK.

Servo motionSave, no plan
Open correction interval
ros2 service call /servo_node/unpause_servo std_srvs/srv/Trigger {}
  1. Use keyboard or gamepad at low speed.
  2. Inspect the TCP position and knife facing from multiple RViz views.
  3. Stop input and wait until the robot is stationary.
  4. Pause Servo before saving.
Close correction interval and save
ros2 service call /servo_node/pause_servo std_srvs/srv/Trigger {}
ros2 service call \
  /box_h_cut_executor/save_cut_debug_point \
  std_srvs/srv/Trigger {}

Saving writes the start observation and correction delta (record status start_saved) and moves the session to stage start_saved. No plan is retained and nothing is planned for the endpoint. It does not move the robot.

Teleoperate to the endpoint and save it

No executor plan; Servo only.

Servo motion
The executor does not plan or execute the traverse to the endpoint. Move the TCP along the cut with Servo at low speed and small increments, watching the blade and the carton.
Teleop to the endpoint, pause Servo, and save
ros2 service call /servo_node/unpause_servo std_srvs/srv/Trigger {}
# Teleop the TCP to the cut endpoint.
# Stop input and confirm the robot is stationary, then:
ros2 service call /servo_node/pause_servo std_srvs/srv/Trigger {}
ros2 service call \
  /box_h_cut_executor/save_cut_debug_point \
  std_srvs/srv/Trigger {}

The second save records the observed endpoint, writes the record with status complete, and ends the session (the executor returns to idle). It retains no plan and never moves the robot.

Finish and close the gates

There is no executor lift stage.

Servo motion
The TCP is still at the endpoint, possibly in contact with the carton. Withdraw it with Servo (for example ; in base_link for +Z), then close the gates.
Close motion gates and stop Servo
ros2 service call /servo_node/pause_servo std_srvs/srv/Trigger {}
ros2 param set /box_h_cut_executor debug_motion_execution_enabled false
ros2 param set /box_h_cut_executor execution_enabled false
ros2 service call /servo_node/stop_servo std_srvs/srv/Trigger {}

Repeat Steps 4–7 for the other cuts, using a fresh snapshot within the age limit.

Apply saved corrections to later planning

Explicit opt-in; one validated file slot per cut.

Planning configuration

Completed records are normally written beneath $HOME/cut_debug_corrections as <cut>_<snapshot_id>.json. Inspect each JSON before loading it.

Set independent correction records
ros2 param set /box_h_cut_executor \
  cut_debug_left_correction_file \
  /absolute/path/to/left_snapshot.json
ros2 param set /box_h_cut_executor \
  cut_debug_middle_correction_file \
  /absolute/path/to/middle_snapshot.json
ros2 param set /box_h_cut_executor \
  cut_debug_right_correction_file \
  /absolute/path/to/right_snapshot.json
ros2 param set /box_h_cut_executor \
  cut_debug_correction_enabled true

A combined or h plan applies each matching record only to its own segment; t_cut and t_cut_handoff (the default pattern is t_cut) contain only left and middle segments, so a set right record is loaded, validated, and left unused. Empty slots remain nominal. The stored along, across, and normal deltas rotate with a newly detected cut; they are not fixed world XYZ offsets.

Disable learned corrections
ros2 param set /box_h_cut_executor cut_debug_correction_enabled false
An enabled configuration with all three paths empty fails closed. A nonempty malformed, incomplete, mismatched, non-absolute, or non-finite record also rejects planning. Each record must contain planning_frame and tool_link equal to the executor's active values; a record missing either is refused. Correction parameters cannot be changed while a session is active or a plan/execution is running (the change is rejected as busy). Translation values must be finite; there is no per-axis magnitude limit. Orientation correction accepts the full finite unit-quaternion range, but application still fails closed unless the corrected tool points into the carton surface.

Abort and recovery

Stop command production first; then clear the retained executor state.

Stop procedure
Software stop and clear
ros2 service call /servo_node/pause_servo std_srvs/srv/Trigger {}
ros2 service call /servo_node/stop_servo std_srvs/srv/Trigger {}
ros2 param set /box_h_cut_executor debug_motion_execution_enabled false
ros2 param set /box_h_cut_executor execution_enabled false
ros2 service call /box_h_cut_executor/clear_plan std_srvs/srv/Trigger {}
  • Use the hardware emergency stop for immediate danger. ROS service calls are not an emergency-stop substitute.
  • clear_plan discards the retained plan and active debug session without commanding motion. While planning or a trajectory execution is running it answers busy instead of waiting; it cannot stop motion (use the emergency stop).
  • After an execution failure, the stage does not advance and the executable plan is removed. Clear the session, diagnose the controller/scene, and start a new session.
  • Never resume from an assumed stage. Read every service response.

Troubleshooting

Treat rejections as safety information, not obstacles to bypass.

No workaround flags
external_snapshot_file is required or snapshot is stale
Set an absolute snapshot .json path and provide a new perception snapshot; the session must start within external_snapshot_max_age_s (240 s in the supplied YAML). debug_allow_stale_snapshot=true only allows RViz inspection: execution of anything loaded with it is refused. Set it back to false, call clear_plan, and start again from a fresh snapshot.
Planning scene is missing a required obstacle
Check that the external snapshot path is valid and detected_carton is present. Also confirm the fixed external camera publishes camera_link and camera_color_optical_frame; camera_pole_collision.py must publish the required camera_pole object before H-cut planning.
Servo service exists but teleop does not move
Check the response from start_servo, call unpause_servo, hold the gamepad enable button if you use the gamepad, and confirm the teleop process publishes on delta_twist_cmds (the Servo command topic in config/servo.yaml). On physical hardware, also verify controller state—but do not bypass safety stops.
Executor reports that execution is disabled or blocked
This is expected until both executor gates are true. Inspect the retained plan before enabling them. These gates are independent from Servo pause state. A message about debug_allow_stale_snapshot means the session was loaded under the plan-only override and can never be executed; clear it and start over from a fresh snapshot.
Save is rejected
The first save is legal only after the start dispatch completed successfully (stage start_executed); the second save follows the first. Confirm fresh (under one second), finite, complete joint states and wait for the robot to become stationary. A save before the start has executed, or after a failed dispatch, is intentionally rejected.
Planning or parameters are rejected during a session
Planning and correction parameters (cut, pattern, tilts, correction files and similar) are frozen while a session is active and rejected as busy while a service call or execution runs. Geometry, clearance, frame and scaling parameters are read-only at any time: edit box_h_cut_executor.yaml and restart the executor. Finish the session or call clear_plan, then change configuration and start over.
A correction file is rejected
Use an absolute .json path and a complete box_h_cut_correction/v1 record matching the parameter slot, planning frame, and tool. Do not edit a record to suppress validation; teach the point again.
