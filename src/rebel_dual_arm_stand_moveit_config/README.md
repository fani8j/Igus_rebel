# rebel_dual_arm_stand_moveit_config

> **Not the real-cell model.** This is the full stand (ZLW lift + sliders, `world` = floor at the lift column) for planning studies and Isaac Sim.
> The real two-arm setup on the test table, with `world` = `arm_left_base_link` and the calibrated arm_right/camera poses, lives in
> `rebel_dual_arm_description` + `rebel_dual_arm_calibration`. Do not mix frames between the two.

MoveIt 2 (**Humble**) configuration, ros2_control controllers and a **plan-only** launch for `rebel_dual_arm_stand_description`. Mock hardware or Isaac
topics only; no real-hardware path. Partly derived from `compal_robot` (MIT, commit `bb76327`), see `NOTICE` and
`rebel_dual_arm_stand_description/THIRD_PARTY.md`.

```bash
export ROS_DOMAIN_ID=<unused id> ROS_LOCALHOST_ONLY=1        # never the real robot's domain (11)
source /opt/ros/humble/setup.bash && source install/setup.bash
ros2 launch rebel_dual_arm_stand_moveit_config dual_arm.launch.py hardware_protocol:=mock_hardware            # plan-only, carton scene added
ros2 launch rebel_dual_arm_stand_moveit_config dual_arm.launch.py hardware_protocol:=isaac_topic use_sim_time:=true use_rviz:=true
python3 src/rebel_dual_arm_stand_moveit_config/scripts/verify_plan_only.py --out result.json                  # smoke test, executes nothing
```
Launch arguments: `hardware_protocol` (mock_hardware | isaac_topic), `use_sim_time` (false), `allow_trajectory_execution` (**false**), `run_move_group`,
`use_rviz` (false), `rviz_config`, `add_cell_scene` (true), `scene_file`, `tool_config`. Spawners run strictly one after the other
(joint_state_broadcaster, gantry_, arm_left_, arm_right_trajectory_controller). With `allow_trajectory_execution:=false` move_group is also given no
controller list, so the plan-only stack logs `No controller_names specified` (expected). `/execute_trajectory` still exists but aborts; checked in
`scan_results/dual_arm_import_20261006/` (`plan_only_execute_probe.txt` ABORTED vs `allow_exec_true_execute_probe.txt` SUCCEEDED, empty trajectory).

`home`: arms upright (all joints 0), lift -0.2 (compal_robot's value; valid, nothing collides), sliders -0.005973 / +0.005973 => arm spacing **s = 0.448 m**.

## Collision matrix
Conservative, no sampling: every parent/child pair (Adjacent), the head-camera parts, the tool links of one arm among each other and with `link6`, and the
arm-internal pairs of OUR `igus_rebel2.srdf` (prefixed per arm). Deliberately enabled: stand <-> sliders, slider <-> slider, arm <-> arm, tool <-> other
arm, tool <-> link4/5. More "Never" pairs could be added by sampling (`tools/cell_planner_check/sample_collisions.py` pattern, >= 20000 samples); not done.

## Carton pose (cell_scene.yaml)
Source: `scan_results/cell_v3_20261004/recommended.json` rank 1 (`r_1269_A0_B0`, fixture BIG370): in the planner frame W the carton centre is
(0.550, -0.084) m, yaw 165 deg (= -15 deg modulo the carton's 180 deg symmetry), h = 0 (carton top at the arm base plane), size 0.32 (seam axis) x 0.37 x 0.18.
W -> world: `p_world = O + Rz(-90 deg) p_W`, O = (-0.001764, -0.179297, 1.1093 + lift_ref) (mid-point of the arm base axes at the arm mount plane; the arm mounts
are rotated -90 deg, so x_w = -Y, y_w = +X, z_w = +Z). With `lift_ref` = -0.2: carton centre (-0.085764, -0.729297, 0.8193), yaw 165 deg about +Z. Cross-check: the
study's "stop corner" W (0.3299, -0.1907) lands on the box corner (+0.1600, -0.1850) in the box frame (to 0.03 mm).
* Confidence: x/y placement and yaw high (frame conventions are explicit and the corner check closes). **The height depends on the lift**: the study fixes the carton
  top at the arm base plane, so the table top is at 0.7293 m only because lift_ref = -0.2 (home). If the lift is run elsewhere the real table must follow
  (`lift_ref` parameter of `add_cell_scene.py`, or edit the yaml).
* The brief said "yaw 15 deg"; recommended.json says 165 deg. 165 deg is used; +15 deg would be the mirror image.
* **Placeholders (not measured):** the carton table is a solid block from the floor (world z = 0) to the carton bottom, x_w 0.12 .. 0.92, 650 mm wide
  (the 0.12 front edge is from the study, the 650 mm width from the test-table note, depth and the solid fill are assumptions). No robot table, no scene
  camera post (the real stand is in the URDF).
* `python3 scripts/add_cell_scene.py --print` prints the resulting objects without ROS.

## Unvalidated
Only plan-only behaviour on mock hardware was tested (see `scan_results/dual_arm_import_20261006/`). No RViz inspection, no execution on the mock controllers, no Isaac Sim, no
real hardware. Knife-tip poses with the tool z axis pointing straight down are only reachable for part of the roll range about the blade axis (see results);
that is a property of the tool geometry, not a scene tweak.
